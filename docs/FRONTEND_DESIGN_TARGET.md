# 前端重构设计目标

## 产品定位

控制窗口不是“功能陈列柜”，而是一块可信赖的预设历史工作台。用户打开后应在三秒内确认：自动保存是否工作、当前有哪些记录、下一步最常用的动作在哪里。

## 信息架构

1. 顶部只保留产品身份、运行状态、立即快照和统一工具入口。
2. 记录、日志、设置是三个互斥工作区，并使用标准 Tab 语义。
3. 记录页默认暴露搜索、常用筛选和视图切换；批量、分组、展开、导入导出、清理等低频操作进入“工具”菜单。
4. 差异对比栏只在用户选中 A 或 B 后出现，不长期占用空间。
5. 底部只显示统计和当前上下文，不再堆放操作按钮。

## 视觉与交互

- 使用 SillyTavern 主题变量，不建立与宿主割裂的第二套主题。
- 桌面窗口最大宽度 1080px，内容区优先展示记录；工具栏可换行但不压缩文字。
- 640px 以下使用全屏工作台，所有主要触控目标至少 44px，筛选横向滚动，不隐藏 Tab 文案。
- 状态、选中、警告不能只依赖颜色表达。
- 动画只用于状态过渡，并遵循 `prefers-reduced-motion`。

## 可访问性

- Tab 使用 `tablist` / `tab` / `tabpanel`、`aria-selected` 和键盘方向键导航。
- 菜单声明展开状态并支持 Escape 关闭。
- 可折叠记录头支持 Enter / Space。
- 图标按钮必须拥有可读名称；设置控件必须有显式标签和说明关联。
- 键盘焦点始终可见。

## 工程边界

- 保留全部现有功能、存储格式、事件和 CSS 钩子，重构不迁移用户数据。
- 新面板样式单独分层，旧样式继续服务二级弹窗；待真实场景稳定后再删除遗留规则。
- 面板骨架使用纯函数生成，允许无 DOM 单元测试。
- 首屏不增加网络请求，不引入 UI 框架，避免扩大插件加载成本。

## 验收标准

- 1280×900、768×900、390×844 三种尺寸无横向页面溢出、文字竖排或不可触达按钮。
- 记录、日志、设置、工具菜单、筛选、视图切换、立即快照和差异选择均可用键盘操作。
- 工具菜单关闭后焦点回到触发器；切换 Tab 后隐藏面板不可聚焦。
- 控制台无新增错误，现有自动化测试全部通过。
- 面板打开、切换和滚动过程中不产生可感知卡顿；列表仍沿用现有节流与增量机制。
